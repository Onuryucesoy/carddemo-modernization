# INTCALC (CBACT04C) — COBOL → Java, test-first

The monthly interest batch `app/cbl/CBACT04C.cbl` (job `app/jcl/INTCALC.jcl`) ported to Java,
proven equivalent with a golden master recorded from the original program.

## 1. Record the legacy behaviour (before any Java existed)

```bash
modern/golden-master/run-cobol.sh <scenario>        # writes modern/golden-master/expected/<scenario>/
```

Compiles the **unmodified** `CBACT04C.cbl` with GnuCOBOL (`-std=ibm -fsign=EBCDIC`), loads the
fixture files into indexed files with the same keys as the VSAM KSDS, runs it with
`PARM='2022071800'` and a fixed clock (`COB_CURRENT_DATE`), and records:

| file | content |
|---|---|
| `sysout.txt` | every `DISPLAY` line |
| `transact.txt` | the 350-byte interest transactions written to `TRANSACT` |
| `acctdata.txt` | the account master after the run, in key order |
| `result.txt` | `RC=0000` or `ABEND U0999` |

Harness-only programs live in `golden-master/cobol/` (PARM driver, `CEE3ABD` abend stub, file
loader/unloader). Fixtures: `seed/` is the shipped `app/data/ASCII` data; the rest are generated by
`fixtures/make_fixtures.py`:

| scenario | what it pins down |
|---|---|
| `seed` | shipped data (all balances zero, blank group ids → `DEFAULT` rates) |
| `month-end` | own-group vs `DEFAULT` rates, 0% group, negative balance, sub-cent interest, cycle reset, last account |
| `overflow` | high-order truncation of `PIC S9(09)V99` / `S9(10)V99` fields |
| `abend-missing-default` / `-account` / `-xref` | the three U999 abend paths and what was already written |

## 2. Prove the Java port matches

```bash
cd modern/interest-service && mvn -B test
```

`GoldenMasterTest` replays every recorded scenario through `InterestBatchCli` and requires
byte-identical output files. `InterestRulesTest` and `ZonedDecimalTest` pin individual rules.

## Behaviour carried over exactly (including quirks)

- `interest = balance × rate / 1200`, **truncated** toward zero to cents (no `ROUNDED`): −833.33 @ 15% → −10.41.
- Overflowing amounts lose high-order digits silently (no `ON SIZE ERROR`).
- No rate row for the account group → `DEFAULT` group for the same type/category; neither → abend U999.
- 0% rate → no transaction, but the account is still rewritten with cycle credit/debit reset to 0.
- **Legacy defect kept for parity:** the last account in TCATBAL gets its interest transaction
  but its balance is never posted (the loop ends before the final `1050-UPDATE-ACCOUNT`).
  Fixing it is a business decision; it is isolated to one spot in `InterestBatch.run`.

## Platform notes

- On z/OS `TRANSACT` is `DISP=(NEW,CATLG,DELETE)`, so after an abend the transaction dataset is
  deleted; GnuCOBOL (and the Java port) leave what was written. Account rewrites done before the
  abend persist on both.
- Uninitialised `TRAN-RECORD` filler is spaces under GnuCOBOL; the Java port writes spaces.
